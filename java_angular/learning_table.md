| **НОМИНАЛЬНАЯ ТИПИЗАЦИЯ** | Класс должен явно указать `implements Playable`. | **STREAMS API** | Конвейерная обработка данных: `list.stream().filter(...).map(...).toList()` [1]. | Цепочки методов массивов в JS: `.filter().map()`. | Заводской конвейер: сырье движется по ленте, проходя этапы сортировки и обработки, перед тем как упаковаться в коробку. | **Gotcha:** Вычисления в стримах «ленивые». Фильтрация и маппинг не начнут выполняться физически, пока в конце цепочки не будет вызван терминальный оператор (например, `.toList()` или `.collect()`) [1]. |
| **IoC-КОНТЕЙНЕР И БИНЫ** | `ApplicationContext` — ядро Spring, управляющее жизненным циклом Бинов (Beans) — объектов-одиночек (Singleton). | IoC-контейнер в NestJS, ручное создание зависимостей `new Service()` в Express. | Дирижер оркестра (Контейнер), который рассаживает музыкантов (Бины) и указывает им, когда и как играть вместе. | По умолчанию все бины в Spring создаются как Singleton (в одном экземпляре на все приложение). Если нужно создавать новый объект при каждом внедрении, требуется явно указать `@Scope("prototype")`. |
| **АННОТАЦИИ СЛОЕВ** | `@RestController` (API), `@Service` (Логика), `@Repository` (БД) — специализированные версии `@Component`. | Декораторы в NestJS: `@Controller()`, `@Injectable()`. | Разные отделы в компании: бухгалтерия, склад, менеджеры. У каждого своя зона ответственности. | Аннотации служат маркерами для Spring. При запуске он сканирует проект (Component Scanning), находит эти классы, создает их экземпляры и связывает их зависимости через конструкторы. |
| **REST CONTROLLER** | `@RestController`, `@RequestMapping("/path")`, `@GetMapping("/{id}")`, `@PathVariable`, `@RequestBody`, `@Valid`. | Декораторы NestJS/FastAPI: `@Controller()`, `@Get(':id')`, `@Param()`, `@Body()`. | Сортировщик на почте: читает адрес на конверте и передает его в нужный кабинет нужному сотруднику. | `@RestController` автоматически сериализует возвращаемые Java-объекты в формат JSON с помощью библиотеки Jackson. Аннотация `@Valid` запускает валидацию полей DTO до выполнения метода. |
| **ГЛОБАЛЬНЫЙ ОБРАБОТЧИК ОШИБОК** | `@ControllerAdvice` + `@ExceptionHandler(MyException.class)`. | Exception Filters в NestJS, декораторы обработки ошибок в FastAPI. | Подушка безопасности или страховой агент, который перехватывает любые аварии и выплачивает компенсацию по стандарту. | Позволяет перехватывать исключения, выброшенные в любой точке приложения (в сервисах или репозиториях), и превращать их в чистые, безопасные JSON-ответы со статус-кодами (например, 404 вместо 500). |
| **JPA ENTITIES & RELATIONSHIPS** | `@Entity`, `@Table`, `@Id`, `@GeneratedValue`, `@OneToMany(mappedBy = "...")`, `@ManyToOne`. | Схема Prisma (`@relation`), модели SQLAlchemy в Python. | Обручальные кольца: муж физически носит кольцо (Foreign Key), а жена указывает, что замужем за носителем кольца (`mappedBy`). | Параметр `mappedBy` всегда ставится на обратной (не владеющей) стороне связи. Он указывает на имя поля в противоположном классе, которое владеет внешним ключом. Без этого Hibernate создаст лишнюю связующую таблицу. |
| **SPRING DATA JPA** | Интерфейсы, наследующие `JpaRepository<User, Long>`. Методы-запросы вроде `findByEmail`. | Репозитории в NestJS, автогенерируемый клиент Prisma. | Умный ассистент, который по фразе «Найди мне коробку по имени Иван» сам понимает логику поиска и приносит вещь. | **Gotcha:** Разработчик пишет только интерфейс. Spring во время старта приложения генерирует класс-реализацию в оперативной памяти (через Dynamic Proxy) и регистрирует его как Бин. |
| **ПРОБЛЕМА N+1 И JOIN FETCH** | `FetchType.LAZY` (по умолчанию для коллекций). Решение: `@Query("SELECT u FROM User u LEFT JOIN FETCH u.posts")`. | Похожая проблема при неоптимизированных инклудах (Prisma `include` без батчинга) или циклах. | Поездка в магазин за каждым ингредиентом отдельно (10 поездок за 10 продуктами) вместо одной поездки со списком (JOIN). | Если обходить коллекцию `LAZY` в цикле, Hibernate сделает 1 запрос для получения списка родителей и по 1 запросу для детей каждого родителя (всего N+1). `JOIN FETCH` принудительно стягивает все данные за 1 SQL-запрос. |
| **АРХИТЕКТУРА FRONTEND** | Полноценный фреймворк (мнение и стандарты «из коробки»). Четкое разделение на HTML, CSS, TS и Сервисы [2]. | Библиотека React (выбор архитектуры, роутера и стейт-менеджера за разработчиком). | Модульный готовый дом с предустановленными трубами и электрикой (Angular) против конструктора Лего (React). | В Angular компоненты выполняют только роль отображения (View). Вся логика запросов к API и хранения состояния выносится в независимые Сервисы (`@Injectable`), которые внедряются через `inject()` [2]. |
| **СВЯЗЫВАНИЕ В ШАБЛОНАХ** | `{{вывод}}`, `[входные_данные]` (Input), `(события)` (Output), `[(двустороннее_связывание)]` (ngModel). | `{вывод}`, `prop={вход}`, `onClick={событие}` в JSX. | Входные данные текут внутрь элемента через коробку `[ ]`, исходящие сигналы летят наружу как звуковые волны `( )`. | Двустороннее связывание `[(ngModel)]` («банан в коробке») автоматически обновляет значение в инпуте при изменении переменной в TS, и наоборот, избавляя от ручного написания обработчиков `onChange`. |
| **НОВЫЙ CONTROL FLOW** | `@if (condition) { ... } @else { ... }`, `@for (item of items; track item.id) { ... } @empty { ... }` [2]. | Тернарные операторы `{cond ? A : B}` и циклы `{items.map(item => ...)}` в JSX. | Встроенный автоматический конвейер, который сам выводит сообщение «Пусто», если на ленте нет товаров (`@empty`). | Начиная с последних версий Angular, этот синтаксис заменил старые директивы `*ngIf` и `*ngFor` [2]. Он работает быстрее, не требует импорта `CommonModule` и встроен в ядро фреймворка. |
| **РЕАКТИВНЫЕ ФОРМЫ** | `FormGroup`, `FormControl`, `FormBuilder`, валидаторы `Validators.required` в TS-классе. | Использование внешних библиотек: Formik, React Hook Form + Yup/Zod. | Виртуальный пульт управления в кабине пилота (TS), к которому просто физически подключаются внешние кнопки из кабины (HTML). | Вся форма, её состояние, значения и правила валидации описываются в TypeScript-классе. Это позволяет легко тестировать формы юнит-тестами без рендеринга HTML-страницы и подписываться на изменения полей как на потоки. |
| **СИГНАЛЫ (SIGNALS)** | `count = signal(0)`, `double = computed(() => count() * 2)`, `effect(() => ...)` [2]. | `useState()`, `useMemo()`, `useEffect()` в React. | Таблица Excel: изменение значения в одной ячейке мгновенно и точечно пересчитывает только зависимую формулу. | **Gotcha:** В отличие от React, изменение Сигнала **не вызывает повторный запуск всей функции компонента**. Angular обновляет строго тот текстовый узел в DOM, который зависит от этого сигнала (мелкозернистая реактивность). Зависимости отслеживаются автоматически, массивы зависимостей не нужны. |
| **RxJS ПОТОКИ (STREAMS)** | `Observable` (источник потока), `Subscriber` (слушатель), подписка через `.subscribe()`. | Promises в JS (асинхронные операции), WebSockets (бесконечные потоки данных во времени). | YouTube-канал (Observable): выпускает ролики во времени. Вы (Subscriber) подписываетесь и получаете уведомления. | **HTTP-запросы в Angular возвращают конечные (finite) потоки**. Они отправляют один ответ и сразу завершаются (`complete`), поэтому от них не нужно отписываться вручную — утечки памяти не будет. |
| **ОЧИСТКА РЕСУРСОВ** | Отписка от бесконечных потоков в `ngOnDestroy()` через `.unsubscribe()`, оператор `takeUntilDestroyed()` [2] или pipe `async` в HTML. | Функция очистки в `useEffect` (возврат из хука: `return () => cleanup()`). | Выключение электроприбора из розетки после завершения его использования во избежание короткого замыкания. | Для бесконечных потоков (WebSockets, интервалы) отписка обязательна. Лучший способ — использование трубы `async` в HTML, которая сама подписывается и гарантированно отписывается при уничтожении компонента. |
| **ОПЕРАТОРЫ RxJS** | `pipe()`, `map()`, `filter()`, `tap()`, `debounceTime()`, `switchMap()`. | Методы массивов в JS, ручная реализация дебаунса и отмены промисов в React. | Фильтры очистки воды на трубе перед тем, как вода попадет в ваш стакан. | **`switchMap`** — важнейший оператор для API. При получении нового значения он автоматически отменяет предыдущий (еще выполняющийся) HTTP-запрос в браузере и переключается на новый, предотвращая гонку запросов (Race Conditions). |

### Архитектурный итог для вашего перехода

1.  **Типизация — ваш друг на обоих концах провода.** В Java типы жестко защищают бэкенд на уровне компиляции и выполнения (JVM). В Angular строгая типизация TypeScript защищает шаблоны и формы на этапе сборки фронтенда.
2.  **Сходство паттернов.** Концепция Dependency Injection (внедрение зависимостей) одинаково работает как в Spring Boot (через аннотации слоев и бины), так и в Angular (через инъекцию сервисов в компоненты) [2]. Поняв её один раз на бэкенде, вы автоматически поняли её на фронтенде.
3.  **Реактивность.** Вы локализуете синхронный UI-стейт на фронтенде с помощью легких **Сигналов** (что концептуально похоже на `useState` в React, но гораздо быстрее за счет точечного обновления DOM), а сложные асинхронные события и работу с сетью доверяете мощным потокам **RxJS** [2].

Этот стек представляет собой единую, строго структурированную экосистему, где стандарты написания кода одинаковы для всех команд в мире. Понимание этих «мостов» поможет вам быстро освоить технологии на практике.
