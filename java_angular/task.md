Проект: **Task Tracker с категориями и «живым» поиском** (Мини-трекер задач).

Этот проект выбран потому, что он заставляет применить на практике абсолютно все «мосты», которые мы разобрали: связи в БД, решение N+1, реактивные формы, сигналы и RxJS-операторы.

### СХЕМА ПРОЕКТА


### Шаг 1. Бэкенд (Spring Boot)

Ваша задача на бэкенде — создать REST API для управления задачами. Каждая задача (`Task`) должна быть привязана к одной категории (`Category`).

#### 1. Модель данных (Entities):
*   Создайте класс `Category` (поля: `id`, `name`).
*   Создайте класс `Task` (поля: `id`, `title`, `description`, `status` — ENUM, `category` — связь `@ManyToOne`).

#### 2. Защита от N+1 в Репозитории:
В интерфейсе `TaskRepository` напишите метод для получения всех задач вместе с их категориями за один запрос:
```java
@Query("SELECT t FROM Task t LEFT JOIN FETCH t.category")
List<Task> findAllWithCategory();
```

#### 3. Входные данные (DTO Records):
Для создания задачи принимайте данные через Java `record` с валидацией [1]:
```java
public record CreateTaskDTO(
    @NotBlank @Size(min = 3) String title,
    String description,
    @NotNull Long categoryId
) {}
```

#### 4. Контроллер (`TaskController`):
Напишите эндпоинты:
*   `GET /api/tasks` — возвращает список задач (использует метод с `JOIN FETCH`).
*   `POST /api/tasks` — создает задачу (принимает `@Valid @RequestBody CreateTaskDTO`).
*   `GET /api/tasks/search?query=...` — поиск задач (в репозитории используйте генерацию запроса `findByTitleContainingIgnoreCase`).

### Шаг 2. Фронтенд (Angular)

Создайте новое приложение через Angular CLI: `ng new task-tracker --standalone` [2].

#### 1. Сервис для работы с API (`task.service.ts`):
Напишите методы для выполнения HTTP-запросов [2]. Сервис должен возвращать `Observable`.

#### 2. Форма добавления задачи (Reactive Forms):
Создайте компонент `TaskFormComponent`. 
*   Используйте `FormBuilder` для создания формы с полями `title`, `description`, `categoryId`.
*   Повесьте валидаторы (обязательность, длина строки) [3].
*   Блокируйте кнопку отправки, если форма невалидна [3].

#### 3. Живой поиск задач (RxJS):
В компоненте списка задач сделайте строку поиска.
*   Используйте `Subject<string>` для отслеживания ввода.
*   Примените цепочку операторов: `map` (очистка пробелов) ➔ `filter` (длина > 2) ➔ `debounceTime(300)` ➔ `switchMap` (запрос к API бэкенда).

#### 4. Фильтрация задач (Signals):
Используйте новые Сигналы Angular для управления локальным состоянием UI [2]:
*   Создайте сигнал текущего фильтра: `activeFilter = signal<'ALL' | 'TODO' | 'DONE'>('ALL')`.
*   Создайте вычисляемый сигнал `filteredTasks = computed(() => ...)` [2], который будет автоматически фильтровать список задач на экране в зависимости от значения `activeFilter` и списка задач из API.

### Главный подводный камень: CORS

При подключении Angular к Spring Boot вы гарантированно столкнетесь с ошибкой CORS (браузер заблокирует запросы с `localhost:4200` на `localhost:8080`).

**Решение:** На бэкенде в Spring Boot добавьте аннотацию `@CrossOrigin(origins = "http://localhost:4200")` над вашим `TaskController` (или настройте глобальный WebMvcConfigurer).

### Как проходить эту практику?

Рекомендуется двигаться последовательно:
1.  **Создайте бэкенд** и проверьте его работу через Postman (или встроенный Swagger / HTTP-файлы в IDE). Убедитесь, что валидация работает и возвращает правильные ошибки 400, а запросы к базе выполняются без N+1.
2.  **Создайте фронтенд**, настройте базовый вывод списка задач с сервера.
3.  **Добавьте интерактивность** — сначала форму создания, затем живой поиск на RxJS, и в конце — фильтрацию списка на Сигналах.
