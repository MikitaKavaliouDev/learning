# Глава 11: Питч — История миграции для собеседования

> «Расскажите о себе» — самый важный вопрос на любом интервью. Если ваш ответ структурирован и показывает бизнес-ценность, вы на 50% ближе к офферу.

Эта глава содержит готовые скрипты ответов на ключевые вопросы о миграции. Используйте их как шаблон, адаптируя под свой реальный опыт.

## 11.1. 2-минутная самопрезентация (Pitch)

Когда интервьюер говорит: *«Présentez-vous»* или *«Расскажи о себе»*, используйте следующую структуру:

### Структура

```markdown
1. Кто я (15 сек)
2. Мой последний проект — миграция (30 сек)
3. Моя роль и сложность (45 сек)
4. Результаты и готовность к новой миссии (30 сек)
```

### Полный текст

> **«Я Full-Stack разработчик с более чем [X] годами опыта в стеке Java и Angular. В своей работе я уделяю особое внимание архитектуре, производительности приложений и культуре качества — Clean Code, SonarQube, автоматическое тестирование.**

> **Моей последней ключевой задачей была комплексная миграция критически важного приложения с устаревшего стека Java 8 + Angular 8 на современный стек Java 21 (Spring Boot 3) + Angular 20.**

> **Это была система с высокими требованиями к доступности (SLA 99.9%). Моя роль заключалась не только в написании кода, но и в предварительном аудите кодовой базы, оценке рисков (Analyse d'Impact), проектировании стратегии поэтапного перехода без остановки бизнес-процессов (без Big Bang) и переводе архитектуры на современные стандарты — Standalone Components, Signals (Angular), Virtual Threads и Jakarta EE (Java).**

> **Благодаря этому опыту я глубоко понимаю как ограничения legacy-систем (Java 6/8, JEE, old RxJS), так и преимущества современных версий, и умею выстраивать процесс TMA/MCO максимально надёжно.»**

## 11.2. «Расскажите о вашем опыте миграции» — полный ответ

### Хронология 2.5 лет

> «Да, это был фундаментальный проект продолжительностью 2.5 года, и для крупного промышленного enterprise-комплекса это стандартный срок. Нужно понимать, что мы не делали "зелёную стройку" (Greenfield) с нуля и **не останавливали работу предприятия** — никакого Big Bang.»

### Фаза 1: Аудит и подготовка (4–6 месяцев)

> **Анализ:** Мы провели Analyse d'Impact — глубокий аудит кодовой базы, выявили EOL-библиотеки, конфликты зависимостей, CVE-уязвимости.**
> 
> **Тесты:** Покрыли старый legacy-код Characterization Tests с Testcontainers — это создало «подушку безопасности» и исключило риск регрессии (Garantie de non-régression).
> 
> **CI/CD:** Настроили SonarQube Quality Gates, две параллельные ветки в Git (legacy и main), автоматический деплой.

### Фаза 2: Бэкенд Java 8 → Java 21 (8–10 месяцев)

> **Jakarta EE:** Самая болезненная часть — миграция javax.* → jakarta.* через OpenRewrite.
> 
> **Hibernate 5 → 6:** Переписали нативные запросы под новый SQM-движок, обновили диалекты PostgreSQL.
> 
> **Spring Boot 2 → 3:** Заменили устаревший WebSecurityConfigurerAdapter на SecurityFilterChain.
> 
> **Performance:** Провели нагрузочное тестирование G1GC → ZGC, настроили Virtual Threads.
> 
> **Resilience4j:** Добавили Circuit Breaker, Retry и Bulkhead для защиты взаимодействия со старыми немигрированными системами.

### Фаза 3: Фронтенд Angular 8 → Angular 20 (8–10 месяцев)

> **Пошаговое обновление:** ng update шаг за шагом (8→9→12→15→17→20) с переключением Node.js через NVM.
> 
> **Смерть NgModule:** Весь проект переведён на Standalone Components с автоматической миграцией через Angular Schematics.
> 
> **Signals:** Заменили RxJS-подписки на Signals — точечное обновление DOM, никаких утечек памяти.
> 
> **Control Flow:** Переписали шаблоны с *ngIf/*ngFor на новый синтаксис @if/@for.
> 
> **Zoneless:** Удалили Zone.js — приложение стало легче и быстрее.

### Фаза 4: Финальное тестирование и документация (2–3 месяца)

> E2E тестирование (Playwright), аудиты безопасности, актуализация технической документации, передача на MCO (Maintien en Conditions Opérationnelles).

## 11.3. «Какие были сложности?» — 3 ключевых вызова

### Сложность 1: Jakarta EE и обратная совместимость

**Проблема:** Замена javax.* → jakarta.* в сотнях файлов. Старые библиотеки (JAXB, XML-парсеры) не поддерживали `jakarta.*` и падали в рантайме.

**Как решили:**
- Использовали **OpenRewrite** для автоматической замены импортов.
- Провели аудит всех `pom.xml`/`build.gradle` зависимостей, обновили или нашли современные альтернативы для EOL-библиотек.

```bash
# Ключевая команда: OpenRewrite
mvn -U org.openrewrite.maven:rewrite-maven-plugin:run \
  -Drewrite.activeRecipes=org.openrewrite.java.spring.boot3.UpgradeSpringBoot_3_0
```

### Сложность 2: Ivy-совместимость старых Angular-библиотек

**Проблема:** Две ключевые UI-библиотеки (datepicker, tree component) не обновлялись с 2018 года и не поддерживали Ivy-компилятор.

**Как решили:**
- Заменили заброшенные библиотеки на современные standalone-аналоги (Angular Material, CDK).
- Критические компоненты переписали вручную, покрыв Characterisation Tests.

```typescript
// Замена: ng2-date-picker (deprecated) → @angular/material
import { MatDatepickerModule } from '@angular/material/datepicker';
```

### Сложность 3: GC и JVM-флаги

**Проблема:** Скрипты деплоя содержали `-XX:+UseConcMarkSweepGC`, удалённый в Java 14. Docker-контейнеры падали при запуске на Java 21.

**Как решили:**
- Заменили CMS на G1GC (стандарт) или ZGC (для low-latency).
- Провели нагрузочное тестирование с JMH для сравнения GC.
- Настроили Heap Dump на `OutOfMemoryError` для анализа утечек через Eclipse MAT.

```bash
# До (Java 8)
java -XX:+UseConcMarkSweepGC -Xms2g -Xmx4g -jar app.jar

# После (Java 21)
java -XX:+UseZGC -Xms2g -Xmx4g -jar app.jar
```

## 11.4. Бизнес-ценность для заказчика (Business Value Integration)

Французские менеджеры обожают, когда технический специалист понимает бизнес-ценность своей работы. Обязательно добавьте эти пункты в ответ:

### 1. Безопасность и комплаенс

> «Мы закрыли десятки CVE-уязвимостей в устаревших библиотеках и прошли Quality Gates в SonarQube с покрытием тестами 80%+»

### 2. Производительность и экономия

> **Backend (Java 21):** Благодаря Virtual Threads и Spring Boot 3, потребление памяти (RAM) снизилось на **30–40%**, а пропускная способность (throughput) выросла в **3 раза**.
>
> **Frontend (Angular 20):** Tree-Shaking в Standalone Components + ESBuild уменьшили размер JS-бандла **с 12 MB до 2.5 MB**. Page load ускорился в **2 раза**.

### 3. Скорость разработки (Developer Velocity)

> **Код стал чище:** Records, Pattern Matching, Switch Expressions убрали тонны бойлерплейта.
>
> **Сборка быстрее:** CI/CD pipeline сократился с 20 минут до 3 минут (Parallel Gradle + ESBuild).
>
> **Найм проще:** Никто не хочет работать на Java 8 и Angular 8. Современный стек привлекает таланты.

## 11.5. Ответы на дополнительные вопросы

### «Почему 2.5 года? Это не слишком долго?»

> «Для крупного промышленного приложения с SLA 99.9% это стандартный срок. Мы не останавливали бизнес-процессы — миграция шла параллельно с поддержкой текущего функционала (BAU). Из 2.5 лет: 6 месяцев — аудит и подготовка, 10 месяцев — бэкенд, 10 месяцев — фронтенд, 3 месяца — стабилизация.»

### «С чего вы начали миграцию?»

> «Мы начали с **аудита и Characterisation Tests**. Нельзя обновлять legacy-код без страховки. На бэкенде — Testcontainers для интеграционных тестов. На фронтенде — выделили критические user scenarios и покрыли их E2E тестами (Playwright). Только после этого начали поэтапное обновление: Infrastructure → Dependencies → Java/Angular versions → Refactoring.»

### «Какой паттерн миграции использовали?»

> **Strangler Fig Pattern — поэтапное вырезание модулей через API Gateway.** Каждый модуль проходил: Feature Toggle → Canary Release → Parallel Run (Diff Validation) → 100% Traffic → Old Module Removed. Это позволило откатить любой модуль за 15 минут без влияния на пользователей.

### «Как обеспечивали качество?»

> **SonarQube Quality Gates:** Покрытие 80%+ для нового кода, 0 blocker/critical issues, код-ревью каждого PR.
>
> **Resilience4j:** Circuit Breaker, Retry, Bulkhead для немигрированных сервисов.
>
> **Четыре глаза (paired code review):** Ни один PR не вмерживался без аппрува минимум одного сеньора.

### «Какие метрики отслеживали?»

> **Velocity:** Module Migration Rate (модулей мигрировано / осталось).
>
> **Quality:** SonarQube Technical Debt Ratio (снизили с 28% до 8%).
>
> **Performance:** Latency P95, Error Rate, Heap consumption, GC pauses.
>
> **Business:** Zero downtime, SLA 99.9% соблюдён.

## 11.7. Полный сценарий ответа на вопрос «Расскажите о вашем опыте миграции»

Итоговый скрипт для собеседования:

> *«На протяжении последних 2.5 лет я занимался комплексной миграцией критически важного industrial-приложения с устаревшего стека Java 8 + Angular 8 на современный стек Java 21 (Spring Boot 3) + Angular 20.*
>
> *Мы следовали **Strangler Fig Pattern**: ни один модуль не мигрировался Big Bang'ом. Каждый функциональный срез проходил через Feature Toggle, Canary Release и Parallel Run. CI/CD был настроен на две параллельные ветки (legacy и main).*
>
> *На бэкенде самыми сложными вызовами были: Jakarta EE миграция (javax → jakarta через OpenRewrite), обновление Hibernate 5 → 6 с переписыванием native queries и переход с CMS GC на ZGC с полным нагрузочным тестированием.*
>
> *На фронтенде мы прошли путь от View Engine до Ivy, от NgModule до Standalone Components и от RxJS-стейта до Signals с Zoneless-режимом. Каждый шаг требовал проверки совместимости библиотек и постепенного рефакторинга.*
>
> *Архитектурно мы разделили монолит на микросервисы через Bounded Context (DDD). Сервисы общаются через gRPC (internal) и Kafka (events). Для resilience используем Resilience4j: Circuit Breaker, Retry, Bulkhead.*
>
> *Инфраструктура полностью переехала в AWS: EKS (Kubernetes), RDS Aurora, MSK Kafka, S3 + CloudFront для фронтенда. Всё описано как Infrastructure as Code (Terraform).*
>
> *Результаты: Memory ↓ 30–40%, Throughput ↑ 3x, Bundle Size ↓ 80%, Zero CVE, Zero Downtime за всю миграцию, SonarQube Quality Gates пройдены.»*

> **Подводный камень (Gotcha):** На собеседовании **не заучивайте текст дословно**. Структура и ключевые цифры должны быть в голове, но рассказ должен звучать как живая история. Используйте **французские термины** (Analyse d'Impact, Garantie de non-régression, Bascule) — это произведёт впечатление на интервьюера из ESN.
